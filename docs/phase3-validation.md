# Shibumi interaction validation

> **Document status: Validation evidence.** This document supports the split,
> drag-and-drop, and persistence gates. `release-readiness.md` contains the
> current acceptance summary.

Phase 3 preserves the V1 interaction outcome without copying V1 persistence or
creating per-style runtime owners. Most evidence is local. the validation system additionally
passes the physical Bottom ghost, successful-drop, and byte-identical
invalid-drop return paths plus process-restart persistence; the remaining
real-Wayland edge cases are listed below.

## Ownership Contract

- `LayoutController` is instantiated once by `Bar.qml` and is the only writer
  of group order and split state.
- Every `BarPanel` owns exactly one `DragSession` for its output.
- Styles receive that session only to render targets, markers, and the ghost.
- Leaving edit mode or destroying the output clears all transient drag state.
- No layout or drag core object owns a process, poller, file watcher, or cache.

## Proven Locally

- target discovery uses actual per-output item geometry;
- simultaneous output sessions do not share source, target, or edit state;
- a valid drop writes exactly one shared group swap;
- target registrations follow changed Repeater `modelData` after a swap;
- same-group and malformed targets never write configuration;
- an invalid drop animates back to the source and then releases the source
  reference;
- the horizontal host window remains edge-local for Omarchy panel anchoring,
  while edit dismissal and drag feedback use separate per-output overlays;
- top and bottom use the same surface composition and edge-local loader;
- within-region and boundary cuts are generated by the pure
  `core/RunGeometry.js` model, including the empty-center merge case;
- G10 retains one quick-access drag identity; G12 and G14 retain their
  independent V1 battery/profile drag identities;
- the real offscreen Quickshell loader creates group composition, run chrome,
  edit affordances, targets, and ghost without QML load errors.

## Remaining Wayland Gates

1. Double-click an empty top-bar area and confirm only that output enters edit
   mode.
2. Drag within one region and across left/center/right; verify one swap and
   persistence after shell reload.
3. Release over empty output space and confirm the ghost returns without a
   layout write.
4. Toggle within-section and both boundary markers, then reload.
5. Enter edit mode on one output, hot-unplug it, and confirm the other output
   retains no ghost or keyboard focus.
6. Repeat on mixed scale outputs and inspect clipping, hit targets, and focus.

Until those checks pass, Phase 3 is locally implemented but not release
accepted.
